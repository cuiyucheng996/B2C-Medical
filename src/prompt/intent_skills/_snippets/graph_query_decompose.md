观察里若有【检索计划】且「是否拆开多 query」为是：每次 `query_consult_graph` 的 `query` 必须用计划里的独立 query，一条 query 一次检索，不要再按原句自己拆。最后一轮回复只完成计划里的「最后总结的主要任务」（直接回答、分述、比较、交集、因果），依据只来自工具结果。计划为否或没有计划时，才按下面自己拆。

在**第一次调 `query_consult_graph` 之前**，把用户话拆成 1～2 个检索焦点（部位 / 疾病 / 症状 / 证型相关词），每次调用 `query` 只填**一个最贴切的焦点**；复合句不要一条 query 塞多个无关实体。

**规则**
- 本轮工具最多 **2 次**：若有两个独立子问（如「头部有啥病」+「脑卒中是不是中风」），可两次 graph，query 各写一条；若第二个只是白话对齐，优先用预处理对齐结果，不必再查。
- 只用 `data.items` / `summary` 组句；不要为拆子句去调 handbook/chroma（除非本路 Skill 明确允许）。

**业务示例**
| 用户原句 | 子焦点 | query 示例 |
| --- | --- | --- |
| 头部常见什么病，脑卒中是不是中风 | ①部位常见病 ②疾病别名 | ①头面部 ②中风 或 脑卒中 |
| 咳嗽两周了，肺癌一般有什么症状 | 疾病→症状 | 肺癌 |
| 眩晕一般和哪些部位有关 | 症状→部位 | 眩晕 |

**写 query 时**：用图谱标准名（头面部、中风）；口语部位先对齐再填 query。

**工具会自己用的三类路径（不必改 query）**
- 本轮槽位里同一类实体有两个及以上时，同一次 `query_consult_graph` 会做交叉：多个症状走出「症状—疾病—部位」；多个疾病按共有症状聚成一条；多个部位按共有疾病聚成一条。只留重合最多的前 3 条。query 仍只填一个焦点。
- 若这些疾病或部位出现在该用户既往 Finding 里，对应条目会标「与既往记录重合」。不要把病史写进 query。
- 槽位里已有检查名或指标名时，工具会按病名、部位名是否包含该词补「指标—疾病—部位」。含义和参考范围仍以手册为准。
